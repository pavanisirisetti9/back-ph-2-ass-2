## AppError Behavior

`AppError` is a custom error class used to handle expected application errors with a specific HTTP status code and message. It allows the application to return consistent error responses instead of using generic errors.

For example, when a product does not exist, the application creates an `AppError` with a `404` status code and the message `"Product not found"`.

Example response:

```json
{
  "success": false,
  "statusCode": 404,
  "message": "Product not found"
}
```

This provides a clear and consistent error response to the client.

## What Each Log File Captures

### combined.log

The `combined.log` file stores general application logs and HTTP request information. It can contain successful requests, server activity, and other information generated by the application.

Examples include:

* GET requests
* POST requests
* PUT requests
* DELETE requests
* Server activity

### error.log

The `error.log` file is used for error-related log information. It helps identify problems that occur while the application is running and makes troubleshooting easier.

## Morgan + Winston Integration

Morgan is used to log HTTP requests received by the Express application. It records information such as the HTTP method, requested URL, response status, and request processing time.

Winston is used as the application's logging system. The Morgan output is connected to Winston so that HTTP request information can be written through the Winston logger.

The integration works as follows:

```text
Client Request
      ↓
    Express
      ↓
    Morgan
      ↓
    Winston Logger
      ↓
Log Files
 ┌───────────────┐
 │ combined.log  │
 │ error.log     │
 └───────────────┘
```

This integration provides structured request logging and makes it easier to monitor and debug the application.
